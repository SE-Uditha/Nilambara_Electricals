# Backup and restore

Configure an explicitly approved private absolute `BACKUP_ROOT`, outside the application and web roots, plus `MYSQLDUMP_BINARY` and `MYSQL_BINARY`. On this Windows installation the clients are in `D:/xampp/mysql/bin`. Restrict the private directory's Windows ACL to the application operator/administrator; backups contain confidential business and authentication data. Encryption at rest for destination metadata does not encrypt the SQL dump itself; use protected/encrypted storage.

`/admin/backups` supports authorized creation, history, file verification and downloads. Download additionally requires `backups.download`. Files are never served by a public URL. A successful dump must finish, be nonempty, and match its recorded SHA-256 before download. Checksum verification is integrity evidence, not proof of recovery. Manual copies are protected from retention. Scheduled copies retain 30 days and at most 30 versions; cleanup requires a recent verified survivor, preserves history and logs deletion/failure. Unknown/corrupt files are not silently removed.

Daily policy defaults to **02:00 Asia/Colombo**, 30 days, maximum 30 scheduled copies. Administrators can change the time/retention/destination without storing database credentials. Historical backups retain encrypted destination metadata. Failure rows, missed-schedule warnings and cloud-copy state are visible. Scheduler overlap protection prevents duplicate scheduled runs.

Windows: run `powershell -NoProfile -File scripts/install-windows-scheduler.ps1`. The single task invokes Laravel every minute in a hidden process; Laravel selects the daily time. The default task uses the logged-in operator. For logged-off unattended operation, configure a dedicated Task Scheduler service account, filesystem permissions and MySQL startup. Keep Windows/MySQL running. Do not also schedule a second daily dump.

Linux: configure exactly one cron entry, replacing absolute paths: `* * * * * cd /srv/nilambara && /usr/bin/php artisan schedule:run >> /srv/nilambara/storage/logs/host-scheduler.log 2>&1`. Laravel's explicit Asia/Colombo timezone determines 02:00 independently of server timezone. Ensure the scheduler account can run the clients and access private storage.

Google Drive is intentionally inactive until configured. Leave `BACKUP_GOOGLE_DRIVE_FOLDER_ID`, `BACKUP_GOOGLE_DRIVE_EMAIL`, `BACKUP_GOOGLE_CLIENT_ID`, `BACKUP_GOOGLE_CLIENT_SECRET` and `BACKUP_GOOGLE_REFRESH_TOKEN` blank for now, as requested. Later authorize an appropriately restricted Drive API OAuth client with offline access and a private destination folder. The adapter obtains an access token, starts a resumable upload, streams the SQL and verifies remote size/MD5. Local SHA-256 remains recorded. Local success and cloud success are separate; cloud failure retains the local copy. No real Drive upload is claimed while configuration is blank. See [Google upload documentation](https://developers.google.com/workspace/drive/api/guides/manage-uploads) and [offline OAuth setup](https://developers.google.com/identity/protocols/oauth2/web-server#offline).

Restore is CLI-only: `php artisan backup:restore ID`. It requires explicit confirmation, exact database name, active administrator identity, `backups.restore`, password verification, a fresh safety backup and maintenance mode. Failure leaves maintenance mode enabled for recovery. Successful import reconnects, verifies core tables/administrator identity, recreates recovery history/audit and exits maintenance mode. Never select a production target without separate explicit authorization and a verified recovery plan.

`php scripts/verify-mysql.php --step11` creates a random disposable local database and exercises migrations, reporting, native storage, checkout races and the actual dump/restore workflow. Recovery rejects an ordinary application database. Its isolated runtime prevents production maintenance-mode changes. No operational records are restored during this check.
